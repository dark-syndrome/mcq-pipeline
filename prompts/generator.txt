<difficulty_rubric>
EASY (Bloom's: Remember/Understand):
- Tests recall of facts, definitions, or basic comprehension
- Answer is directly stated in the source
- Example: "Which protocol is used for short-range wireless communication in IoT devices?"

MEDIUM (Bloom's: Apply):
- Tests application of a concept to a specific scenario
- Requires using knowledge, not just recalling it
- Example: "A sensor reports temperature every 30 seconds to a cloud server with intermittent connectivity. Which IoT communication pattern is most appropriate?"

HARD (Bloom's: Analyze):
- Tests ability to break down a problem, compare options, or identify causes
- Requires reasoning across multiple concepts
- Example: "An ESP32-S3 project consumes excessive battery during sleep. Given the configuration below, which factor most likely explains the high current draw?"

EXPERT (Bloom's: Evaluate/Create):
- Tests judgment between trade-offs or synthesis of new approaches
- Requires weighing alternatives with no single obvious answer until reasoned through
- Example: "When designing a fleet of 10,000 battery-powered sensors reporting daily, which combination of protocol and architecture best balances energy use, latency, and operational cost?"
</difficulty_rubric>

<quality_criteria>
Every question you generate MUST satisfy:

1. **Source-grounded**: The correct answer must be explicitly supported by the source content. You must provide a verbatim excerpt from the source that justifies the answer.

2. **Uniquely correct** (for single_correct type): Exactly one option must be correct. No "best answer" between two arguably correct options.

3. **Plausible distractors**: Wrong options must be tempting to someone with partial knowledge. They should reflect common misconceptions, related-but-distinct concepts, or partial truths — never absurd or obviously wrong.

4. **Independent of options ordering**: The question must not contain phrases like "all of the above" or "none of the above" unless absolutely necessary.

5. **Self-contained**: A reader should not need to see other questions to understand this one.

6. **Difficulty-matched**: The cognitive demand must match the requested difficulty per the rubric above.

7. **Clear and unambiguous**: No double negatives, no trick wording, no ambiguous quantifiers.

8. **Technically precise**: Use exact terminology from the source.

9. **Stem economy**: The scenario must supply only the context needed to make the decision unambiguous. Do NOT front-load the stem with details that are irrelevant to the question being asked. Every sentence in the stem should be load-bearing.

10. **Source-phrase independence**: The correct answer must NOT contain phrases lifted verbatim from the source_excerpt. Paraphrase the concept; test understanding, not phrase recall.

11. **Option length parity**: The correct answer must not be visibly longer than the distractors. If the correct option requires more words to express precisely, expand the distractors to match length. Target: correct option word count within ±20% of the median distractor word count.
</quality_criteria>

<anti_patterns>
DO NOT generate questions like these:

BAD: "Which of the following is true about MQTT?"
WHY: Generic opener — doesn't tell the learner what cognitive task they're doing.

BAD: "What is the purpose of the topic field in MQTT?"
WHY: "What is" tests definition recall, not understanding. Reframe as a scenario where the topic field matters.

BAD: "According to the text, what does the author say about MQTT?"
WHY: Tests reading, not understanding. Trivia trap.

BAD: "Which of these is NOT a feature of ESP32-S3?
   A. Wi-Fi
   B. Bluetooth
   C. A built-in coffee machine
   D. RISC-V cores"
WHY: Absurd distractor (C) makes the question trivial.

BAD: "MQTT is a _____ protocol.
   A. lightweight publish-subscribe
   B. heavy point-to-point
   C. visual rendering
   D. database query"
WHY: Only one option is even in the right category. Distractors aren't plausible.

BAD: "What is the best protocol for IoT?"
WHY: No single correct answer; depends on context not provided.

BAD (stem inflation): "A software developer is designing a medication dispenser that has a load cell, an RTC, a buzzer, an LED display, a 15-minute compliance window, and an SMS escalation path to caregivers. Which component is an actuator?"
WHY: The scenario lists five details; only one matters for the question. Trim to what the question actually needs.
</anti_patterns>

<distractor_design_guidance>
For each question, design distractors using these strategies:
- **Misconception-based**: A common wrong belief about the topic
- **Adjacent concept**: A related concept that's similar but distinct
- **Partial truth**: True in some contexts but not the one specified
- **Surface similarity**: Looks right by keyword match but is semantically wrong

For each distractor, briefly state why a student might be tempted by it. This rationale is part of the output.

Distractor length: aim for each distractor to be as long as the correct answer. If the correct answer is concise, keep distractors concise too. Length parity matters — a long correct answer surrounded by short distractors is a giveaway.
</distractor_design_guidance>

<stem_pattern_guidance>
Each question must declare a stem_pattern. Use the following definitions:

- definition:  Tests what a term means (only acceptable at EASY difficulty)
- scenario:    Places the concept in a real-world situation (use for MEDIUM+)
- debugging:   Presents a broken or misconfigured system and asks for diagnosis
- comparison:  Asks the learner to distinguish between two or more approaches
- procedure:   Tests knowledge of steps in a process or workflow

Aim for no more than 2 questions of the same stem_pattern in a single batch.
At MEDIUM difficulty and above, prefer scenario, debugging, or comparison patterns.
</stem_pattern_guidance>

<correct_answer_position_guidance>
Distribute the correct answer label across A, B, C, and D approximately evenly across the batch.
Do not place the correct answer in position C or B for more than 2 questions in a row.
</correct_answer_position_guidance>

<code_snippet_question_guidance>
The concept map includes CODE EXAMPLES sections with testable_behaviours and line_annotations.
When code examples are present, generate questions that embed a short code block directly in the
question stem using markdown triple-backtick fences.

Rules for code-snippet questions:
- Keep the code block short: 5–15 lines, focused on a single concept or decision point
- Use the code exactly as it appears in the source, or a minimal adaptation of it
- The question should require the learner to trace execution, identify a bug, predict output,
  or explain why a specific line behaves the way it does
- Use stem_pattern: debugging (for broken/misconfigured code) or scenario (for predict-the-output)
- The source_excerpt for these questions should include the code block and surrounding explanation

Example stem format:
  "A developer writes the following ROS 2 node:
  ```python

  node = rclpy.create_node('sensor_node')
  rclpy.spin(node)
  node.destroy_node()
  rclpy.shutdown()
  ```
  The node starts successfully but the terminal blocks indefinitely after launch.
  What is the most likely cause?"

Target: at least 20–25% of questions in each batch should include a code block in the stem,
whenever the concept map contains code examples.
</code_snippet_question_guidance>

<ordering_question_guidance>
When the question type distribution includes "ordering", generate questions that test whether the
learner knows the correct sequence of steps for a procedure, setup workflow, or algorithm.

Rules for ordering questions:
- Draw from the PROCEDURES section of the concept map — only create ordering questions for
  concepts that have clear, non-interchangeable sequential steps
- All options must have is_correct: false
- The correct_order field must list the option labels (e.g. ["B", "D", "A", "C"]) in the
  correct sequence
- Each option should be one meaningful, self-contained step (not a sub-point)
- The question stem should ask: "In what order should the following steps be performed?" or
  "A developer is setting up X. Arrange these steps in the correct sequence."
- Distractor rationale for each option should explain why a learner might place it out of order
  (e.g. "Learners often initialise the subscriber before the publisher is ready")

Target: approximately 20% of questions in each batch should be ordering type when mixed question
types are enabled, provided the concept map has enough procedural content.
</ordering_question_guidance>
